# Task V12: independent unpruned confirmation of M(12) = 40

Results folder: `bruteforce/results/V12/V<i>/`, where i ∈ {0, 1, 2, 3} is given in your prompt.
Wrap up by **21:15 UTC**.

## Background

Task M12 (`bruteforce/results/M12/`) ran a *pruned* enumeration: geng with a PRUNE
hook that rejects intermediate graphs whose conflict graph Q needs more than 12
colours. It output **no** 12-vertex graph with 41 edges, which gives M(12) = 40.

Pruning is the step most likely to hide a bug. This task removes it:

- every one of the 2,411,961,516 isomorphism classes of 12-vertex, 41-edge graphs
  goes through a checker you write yourself;
- four agents split the work, and agent i takes the res/mod shards r ≡ i (mod 4)
  of `geng -q 12 41:41 r/512`, so 128 shards each.

## Steps

1. **Build geng.** nauty's own site is blocked here. Get the source from PyPI:
   `pip download --no-binary :all: --no-deps pynauty`, unpack it, then in
   `src/nauty2_8_8` run `./configure && make geng`. Record the version.

2. **Write your own checker.** Do not use or read the code in
   `bruteforce/results/M12/src`, `bruteforce/results/SAT/` or `bruteforce/data/first-run/src`.
   Write a C program that reads graph6 on stdin and, for each graph G on n vertices,
   decides whether Q(G) can be properly coloured with K = n colours (README definitions).
   - **Fast path:** find a clique of size K + 1 in Q. Then G is bad.
   - **Otherwise:** run an exact colouring search, either DSATUR branch and bound or a SAT
     call. The SAT call is allowed, but it must be your own encoding.
   - **Counts:** record how each graph was decided, as `graphs`, `bad_by_clique`,
     `bad_by_search` and `good`.
   - **Good graphs:** print each one as graph6 together with a colouring, and re-verify that
     colouring with a separate, deliberately simple 4-cycle enumeration.

3. **Validate before the main run.** Use unpruned geng plus your checker, and compare with
   these known counts of good graphs (isomorphism classes):

   | n | e | good |
   |---|---|------|
   | 7 | 14 | 5 |
   | 7 | 15 | 0 |
   | 8 | 17 | 45 |
   | 8 | 18 | 0 |
   | 9 | 23 | 3 |
   | 9 | 24 | 0 |
   | 10 | 30 | 2 |
   | 10 | 31 | 0 |
   | 11 | 34 | 131 |
   | 11 | 35 | 0 |

   Every row must match. n = 11 is 15–25 M graphs per edge count, so run it sharded
   across your cores. If any count differs, stop and report it; that is a result in itself.

4. **Main run.** For each of your 128 shards:
   - run `geng -q 12 41:41 r/512 | checker 12`;
   - append `r, graphs, bad_by_clique, bad_by_search, good, wall_s` to `shards.tsv`;
   - use all cores; M12 measured about 116 s per shard on one core with its checker;
   - commit `shards.tsv` at least every 30 minutes.

5. **Totals.** Report your 128-shard sums: graphs, bad_by_clique, bad_by_search and good.
   The four agents' graph totals must add up to 2,411,961,516 (the Pólya count).
   Give your own total so that this can be checked.

## Output

- `REPORT.md`: placement, geng version, checker design, the validation table, shard sums,
  any good graph (with its certificate), and timings.
- Checker source in `src/` (binaries in `.gitignore`).
- `shards.tsv`.
